# M16 e2e and judge runs: what was executed

Every fleetify run of the M16 judge work, one row each, numbered in the order they started. It is generated from the run records (`run.json`, `results.jsonl`, `judge.json`) and the recipe files, so each row matches a record on disk. The records are in the session scratchpad, not in this repo. Judge runs against scripted fixtures have no coding agent: the change is applied by a `prepare` script.

## Columns

- **complexity:** readme change, dep update, bigger refactoring (the 1571-line formatting sweep and the 1471 and 1555-line real commits), test fix (the gaming task, honest fix), test edit (the gamed control), bad fixture (hand-built, expected to fail), small change (real commit).
- **source server and repository:** all runs use GitHub. `fleetify-m16-templator` is the test repository. `fleetify-m16-positive` holds the real-commit fixtures.
- **source commit:** the base the run started from. The templator bases are `main` (a1dd380) and `m16/base-broken` (3823c67) at the time of writing. The positive rows name the commit itself.
- **diff from:** which coding agent produced the change, from the hash of the applied patch. `scripted` means a hand-applied fixture with no agent.
- **coding agent and model:** Claude Code (`claude-haiku-5-5`), Copilot CLI (`auto`), opencode (`llamacpp/qwen3.8-flash-next`, the local model). The Copilot model `auto` was logged as `mai-code-1.1-flash` in the e2e round.
- **judge:** the judge tool and model from `judge.json`. Jev runs use `jev-1.14.0` with min confidence 0.5. "level session" is the judge reusing the executor's agent and model.
- **runtime:** the whole run's wall time, then the judge call's time.
- **result:** what fleetify did (`pushed`, `guard_violation`, `needs_review`) and the judge verdict.
- **CI:** every run ended before any merge request was opened (`open_mr = false`, `wait = false`, `merge = "off"` in all 124 recipes), so **no CI ran in any row**.
